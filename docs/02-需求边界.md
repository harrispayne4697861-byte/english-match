# 02 · 需求边界（红线，改动前必须对照）

## A. 硬约束（不可改动）

| 编号 | 约束 | 来源 |
|---|---|---|
| A1 | 零预算：不买服务器、不买素材、不买域名 | 用户 |
| A2 | 单人开发，碎片时间，无代码基础，全程靠 AI 生成代码 | 用户 |
| A3 | **运行设备是手机**，所有设计以手机端为准 | 用户 |
| A4 | 免费、无广告、无内购、无变现 | 用户 |
| A5 | 覆盖幼儿园 / 小学 / 初中三档，各档风格不同 | 用户 |
| A6 | 后续要能（低成本）包装成微信小游戏 | 用户 |

## B. 数据边界（不可越线）

| 编号 | 规则 |
|---|---|
| B1 | 孩子信息（年龄段、年级）**只存本地 localStorage，绝不上报** |
| B2 | 上报内容仅限匿名使用事件：随机 deviceId + 关卡 + 成绩 + 时间戳 |
| B3 | 绝不上报：姓名、生日、头像、性别、openid、设备型号、位置、IP 落库 |
| B4 | 用户可一键清空全部本地数据 |
| B5 | 必须有「隐私说明」页面，写清收集什么、不收集什么、怎么删 |

## C. 技术边界

| 编号 | 规则 | 原因 |
|---|---|---|
| C1 | **零构建**：不需要 npm / Vite / TypeScript 编译 | 用户机器 PATH 里没有 node（已实测） |
| C2 | 纯静态：无自己的服务器（后台用免费 Serverless） | 零预算 |
| C3 | 代码分层：`core-*` 纯逻辑文件里**不允许出现 `document`** | 将来转小游戏时逻辑层可 100% 复用 |
| C4 | 不引入大型框架（React/Vue） | 学习成本与调试成本过高 |
| C5 | 所有交互必须支持触摸，热区 ≥ 44×44 px | 手机端 |

## D. 内容边界

| 编号 | 规则 |
|---|---|
| D1 | 词库只使用 **ECDICT（MIT）** 作为主数据源，随包保留 LICENSE 与出处 |
| D2 | 音标若补充，只用 ipa-dict 的 **en_US**（en_UK 上游是 GPL，禁用） |
| D3 | 不使用任何无 LICENSE 的开源仓库代码或数据 |
| D4 | 不使用教材原版词表整表打包（版权风险），自行按课标整理 |
| D5 | 分级由需求方校核，AI 不得声称"教研级准确" |

## E. 合规边界

| 编号 | 规则 |
|---|---|
| E1 | 不收集不满 14 周岁儿童的个人信息（年龄段/年级不构成可识别身份） |
| E2 | 不设账号、不设付费、不设社交 → 保持未成年人保护风险最低档 |
| E3 | 若未来转微信小游戏，必须先重读 `07-调研结论.md` 第 2 节（防沉迷时间限制是产品级杀手） |
