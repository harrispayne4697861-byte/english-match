# 05 · 移动端设计要求（硬性）

> 前提：**运行设备是手机**。所有设计以手机竖屏为准，电脑上只是"能用"，不作为设计目标。

## 1. 视口与布局

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, user-scalable=no">
```

| 要求 | 说明 |
|---|---|
| 竖屏优先 | 首版**只支持竖屏**，横屏时提示"请竖屏游玩" |
| 满屏 | 用 `100dvh`（不用 `100vh`，避免移动浏览器地址栏导致溢出） |
| 安全区 | 顶部/底部留 `env(safe-area-inset-*)`，适配刘海屏与手势条 |
| 禁止缩放 | `user-scalable=no` + `touch-action: manipulation`（防双击缩放） |
| 禁选中 | 卡片加 `user-select: none`，防长按选中文字 |
| 禁滚动穿透 | 弹层打开时锁 body 滚动 |

## 2. 触控规范

| 项 | 要求 |
|---|---|
| 最小热区 | **44 × 44 CSS px**（iOS HIG 下限），卡片实际远大于此 |
| 事件 | 统一用 `pointerdown` / `pointerup`，不混用 click + touchstart（防重复触发） |
| 视觉反馈 | 按下瞬间缩放 0.96 + 变暗，抬起恢复，延迟 < 100ms |
| 防误触 | 卡片间距 ≥ 8px；消除动画 200ms 内锁定输入 |
| 防连点 | 同一张牌 250ms 内重复点击忽略 |

## 3. 屏幕适配

| 项 | 要求 |
|---|---|
| 棋盘尺寸 | 由屏宽决定：`棋盘宽度 = min(屏宽 - 32px, 440px)`，格子边长 = 棋盘宽 / 列数 |
| 字号 | 用 `clamp()` 或相对单位，禁止写死 px 导致小屏溢出 |
| 中文释义 | 长释义自动缩字号（`font-size` 分两档），**不允许换行超过 2 行** |
| 测试尺寸 | 至少覆盖 320×568（小屏）、375×667、390×844、430×932 |
| 大屏 | 平板/电脑上棋盘居中，最大宽 440px，不拉伸 |

## 4. 性能

| 项 | 要求 |
|---|---|
| 动画 | 只用 `transform` / `opacity`（GPU 加速），**不动画 `width/height/top/left`** |
| 图片 | 使用 WebP/PNG，单张 ≤ 100KB；图标优先用 Emoji 或 SVG |
| 首屏 | 总资源 ≤ 500KB（不含词库） |
| 词库 | 按年龄段分文件，只加载当前档 |
| 音效 | 首次交互后才初始化 AudioContext（移动端自动播放限制） |

## 5. 微信内置浏览器特别注意

| 风险 | 应对 |
|---|---|
| `speechSynthesis` 可能不可用 | **朗读不得作为必需路径**；不可用时静默降级，不报错 |
| 音频自动播放被拦 | 必须由用户点击触发首次播放 |
| 页面缓存激进 | 资源加版本号（`style.css?v=3`） |
| 下拉刷新误触 | 游戏页禁用下拉刷新（`overscroll-behavior: none`） |
| 分享卡片 | 网页版无微信 JS-SDK，分享是普通链接（已知限制） |

## 6. 验收清单（每次改动后过一遍）

- [ ] 手机上竖屏打开，无横向滚动条
- [ ] 底部按钮不被手机手势条遮挡
- [ ] 双击卡片不会缩放页面
- [ ] 长按卡片不会选中文字/弹出菜单
- [ ] 棋盘在 320px 宽的小屏上不溢出
- [ ] 弹层打开时背景不跟着滚
- [ ] 关掉网络后重新打开，进度仍然在
